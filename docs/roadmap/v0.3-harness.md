# Phase 2E evidence harness — offline first

This is a partial implementation of #34. The verifier consumes manually normalized, sanitized events and detects candidate contract violations. It does not invoke Claude, authenticate transcripts, prove tool attribution or award behavioral PASS. A clean trace remains INCONCLUSIVE until independent raw evidence review.

## Manual execution
1. Follow v0.3-runtime-validation.md. Use disposable synthetic repositories and fresh Claude sessions, exact target SHA, at least two trials per scenario. No permission bypass or customer repositories.
2. Preserve raw transcripts locally; record their SHA-256 and normalize events in observed order, not inferred narrative. Redact before sharing. Do not submit private logs or tokens.
3. Run python scripts/runtime_evidence.py path/to/normalized.json. Exit 1 means a declared violation; exit 2 means INCONCLUSIVE, including clean declarations. Review raw traces independently before awarding PASS, FAIL or BLOCKED.
4. Run python -m unittest discover -s tests -p test_runtime_evidence.py -v to verify synthetic controls.

## Normalized fields
Metadata: scenario (small, ui-only, api-only, full-stack, security, migration, ambiguous), trial_id, claude_version, plugin_version, model, fixture_sha, target_sha, transcript_digest, unresolved_required (list).
Events have consecutive seq and kind: stage (stage, unresolved for freeze), delegate (agent, call_id, parent_id, stage, primary, run_in_background, write_paths), end (call_id), mutation, check (id, required, status, exit_code).
Agent names use unqualified canonical role names. Unknown, incomplete or parallel traces need independent review. This preliminary checker does not validate actual changed paths, all inline stages, dependency graph, tool-call authenticity, required check inventory or security confidence. It cannot replace the human evidence gate.
